# Moebius 0.13.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.
Its contracts may change in any later release without a way to migrate.

## A retro proposal with mixed trials is a person's decision

A proposal's status came from all its trials, so one negative trial made the whole proposal `negative`: it got no inbox
item, `POST /v1/proposals/{id}/merge` answered 409, and a trade-off never reached a person at all. A proposal whose own
trials are at least half positive — of the trials that ended, a trial ends when it is positive or negative rather than
skipped or failed — and whose regression set is clean is now `mixed`: it keeps its inbox item with the outcome and the
reason of every trial, and a person merges or dismisses it deliberately. It stays `negative` when a regression trial
failed or fewer than half of its ended trials are positive.

The token factor of a trial was fixed at 1.5 times the tokens of the card's first code run, so a proposal that is good
but slow could never be positive. It is now `[trial] token_factor` in `moebius.toml`, with 1.5 as its default.

## A column script can merge the change

A repository's settings can merge without a person: `moebius.merge_change(reason)` merges the card's change on the
forge, resolves its inbox item and moves the card to `Done` at once. The judgement records the column's script
(`script:<column>`), so the Retro and the training export can tell a policy that decided for every card of a column
from a person's merge. A script still cannot do what only a person may: the harness configuration repository's
protected branch stays refused. The default `merge.luau` keeps waiting for a person; merging without one is a
repository's explicit choice, which overrides the script in its settings.

## Every run cleans up its own scratch

A chat or code run often left fresh checkouts, per-revision build trees, `mktemp -d` directories and test temporaries
behind in the shared `/tmp`, which grew by hundreds of gigabytes, and only a person could clean them up — the built-in
no-destructive-commands rule rightly refuses a recursive delete in a shared temporary directory. Every run is now
started with a scratch directory of its own, `<data dir>/runs/<id>/scratch`, with `TMPDIR`, `TEMP`, `TMP` and
`MOEBIUS_RUN_SCRATCH` pointing at it. The rules allow a recursive delete and a redirect or tee inside that directory
alone, so a run can tidy up after itself without either rule being weakened anywhere else, and the supervisor deletes
the directory when the run ends, whether it succeeded, failed or was killed.

## The retro report stays bounded

The report a retro sends to its analyst grew without a bound: a card sent back from review repeated its findings in
every round it was reviewed, and a busy day crowded the prompt — up to about 38 MB, which the provider refused with a
400. Each kind of error now keeps at most 100 entries, its earliest ones, and a card sent back from review keeps only
the latest entry of each kind per card. A run that settled with no answer at all is no longer counted as succeeded:
its retro reads as `failed`, with the reason among its warnings.

## The chat window grows with the page

The chat window and the package sheet it shares a slot with keep their fixed narrow width no longer: from a wider
desktop they grow to 416 px and at 1536 px to 480 px, and the pages reserve the room, so the sheet covers less of the
work.
