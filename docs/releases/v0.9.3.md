# Moebius 0.9.3

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.

## What changed since 0.9.2

- **Workflows** (#216 to #220, #225): a workflow run is stored with what each node did, node parameters can be filled
  from earlier nodes with expressions, a run executes node by node, a for-each node fans out and gathers, workflows
  are read, saved and deleted through the API and the command line, and the web app has the Workflows list,
  definition and run pages. The board's workflow is now called the Kanban.
- **Labels from a column script**: `moebius.set_label(label, present)` gives the card's issue a label, or takes it
  away, on the forge too. The default scripts give `in-progress` while a card is in `In progress` or `In review` and
  take it away elsewhere and when the card is stuck.
- **The bridge no longer touches the agent's process.** The Pi-Bolt bridge blocks no tool call, redacts, cuts,
  compresses or hides nothing; it only offers the tool `lessons`. What the model has read never changes, so its prompt
  cache holds. This ends `tool_output.hide_after_turns` (still read in old files, ignored), `--hide-outputs-after`
  and the field in the agent editor; the rest of the `tool_output` table is accepted and has no effect.
  - **The rules and the guard no longer act on a Pi-Bolt run's tool calls**, and secrets in tool results are no longer
    redacted there. MCP tool calls are still checked by the gateway.
- Publishing a rewritten card branch uses a lease; a new card can be stored held until its blockers are set;
  Anthropic OAuth requests are shaped for subscription billing.
