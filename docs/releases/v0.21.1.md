# Moebius 0.21.1

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.
Its contracts may change in any later release without a way to migrate.

This release shapes the review flow of the software factory: how many rounds of the Reviewer a pull request gets is a
setting, an author's committed measurement is accepted once the Reviewer approves, a repository whose forge reports no
checks is still reviewed on its own, and a followed pull request's card moves with who is to act.

## The software factory

The settings are in the "Working with others" page of a repository, and the rules of the rounds are in the
[factory reference](../reference/factory.md).

- **The review round limit is a setting** (#780). `review_round_limit` holds how many rounds of the Reviewer a followed
  pull request gets: 0 to 100, 3 by default, 0 for no limit. When the rounds are spent, the next `/done` is answered no
  and the owner is asked to look with a `review_rounds_spent` inbox item for the card; the answer names the number
  ("reviewed 3 times already"). Rounds a person asked for (`POST /v1/changes/{id}/review`) do not count.
- **An author's committed measurement is accepted with the approval** (#781). When the Reviewer approves the pull
  request, the measurement its author committed with the change is accepted for the head it was read at, so the author's
  own numbers need no second pair of hands.
- **A head with no checks at all is waited for as green** (#789). `review_on_green` counts a head the forge reports no
  check runs or commit statuses for as green: its few minutes count from the first poll that finds it so, and the issue
  is told the head has no checks. Such a head is marked `without_checks` in the store; when checks show up for it later
  it is waited for like an unproven one — pending or red stop a round, and the wait starts over when they pass, unless
  a round was asked for already.

## Cards

- **The card moves with who is to act** (#782). A round of the Reviewer that ends with changes asked for moves the card
  to In progress with the review's summary as its note (the author's turn); a card already In progress or Done stays
  where it is. When a round starts again, a card that waited in In progress goes back to In review and its note is
  taken away (the Reviewer's turn).
- **A `/done` is not lost right after a push** (#783). A `/done` is answered against the pull request as the forge has
  it now: the seconds between a push and the next poll no longer lose it.

## Upgrading

- The store gets two new columns when the server starts: `review_round_limit` on the flow settings, 3 by default, and
  `without_checks` on `green_heads`. Nothing else changes for an existing server.
- A server that polls GitHub should hold the permission to **read commit statuses** now: without it the forge reports
  no checks for every head, and every head then counts as green for `review_on_green` right away.
