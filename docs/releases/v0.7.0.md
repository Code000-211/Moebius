# Moebius 0.7.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.

## What changed since 0.6.0

All of it in the web app and the server; the desktop app has no new screens.

- **The board is an issue tracker** (#191).
  - **Sub-issues** lie as a stack in their parent's column: the parent's card says how many are done and opens the
    stack in place. New issue and a card's menu set a parent; GitHub's sub-issues are used, GitLab and Forgejo get a
    `Part of #n` line.
  - **Blocking** is written as well as read, in the dock, through the API and with `moebius issue blocker`, using each
    forge's own dependencies where it has them; cycles are refused.
  - **Labels**, **claims**, **comments**, **closing and reopening** an issue and **editing** its title and body, in
    the dock and with `moebius issue …`; `moebius issue list` filters by parent, label, state, claim and blocking.
  - The default workflow does not code a parent while it has open sub-issues, and closes it when the last one is done
    (unless it has a change or run of its own, or a person reopened it). Only sub-issues from trusted authors, or
    approved ones, count. A card closed without a merge is recorded as `closed`, no longer as `merged`.
- **Matt Pocock's `wayfinder` skill** (#192) plans a piece of work too big for one session as a map of decision
  tickets. Say `/wayfinder` in a chat with the Grilling partner: the map is an issue labelled `wayfinder:map` with its
  tickets as sub-issues, worked one per session until the way is clear. The Coder never starts on a `wayfinder:*`
  issue. The Grilling partner may only create and change `wayfinder:*` issues, and only in its own chat's repository.
  `domain-modeling`, `research` and `prototype` come with it, and the vendored skills are at a newer upstream commit.
