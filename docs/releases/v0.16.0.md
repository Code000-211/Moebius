# Moebius 0.16.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.
Its contracts may change in any later release without a way to migrate.

This release gives the web app and the desktop app a new look. It was designed screen by screen against mockups and
written down as a new standard, [`docs/design-web.md`](../design-web.md), with the decisions and the approved mockups in
[`docs/design/web-redesign/`](../design/web-redesign/DECISIONS.md) and the reasons in
[ADR 0023](../adr/0023-a-quieter-light-first-standard.md). Read "Upgrading from 0.15" before you install it: the server
and the desktop app must both be 0.16.0.

## A new look

- **Light first and quiet.** The light theme is the default (the dark one is a neutral dark), text is 13px and rows are
  36px, indigo marks only what it means (the primary button, the chosen tab, counts, the chosen row), orange only what
  needs you and green only what is running. Hairlines take the place of boxes, and nothing is on screen that helps
  nobody: no key boxes, no hint bars, no column headers, no sentence under a page's title.
- **The shell.** The content is one panel beside a slim sidebar: the server's switch and search at its head, then Inbox,
  My issues, Fleet, the projects, Wiki, Cycles, Views and More, and Settings at its foot. In the desktop app the window's
  buttons sit in the page's header and there is no title strip. Below about 1000px the sidebar hides behind a button.
- **Lists.** Inbox, My issues, a project's list and Fleet share one row: status icon, id, title, a few pale words of
  reason, the owner's avatar and the age, with the one action a row needs (such as "Approve plan") on the row. The
  Inbox groups what needs you, what runs and what is done; Fleet has the tabs Active and Finished and a Pause all.
- **The board.** Flat cards with a hairline; a second pale line only when an agent runs, the card needs you, or it is
  blocked or waiting. Each column scrolls on its own.
- **A card** opens as a window in the middle of the page it was opened from, with "Open as page". It reads as its
  thread: comments, moves, the code run and the review as one line each, and one block where the agent needs you. Its
  properties are in its menu.
- **The agent** is one "Ask Moebius" field at the foot of a page; asking, or an answer, opens it as a panel on the right.
  A step says what was done in a few words, code stands in a dark block with its language, file and Copy, and an answer
  that proposes a plan carries Approve plan and Reply. Earlier conversations have a list inside the panel.
- **Settings** is one page with a searchable sub-navigation (You, Agents, Automation, Insight, Server) that holds the
  areas that used to fill the sidebar. Appearance has "Show thinking expanded" (kept per person), "Reduce motion" and
  "Blur on menus".
- **Rules, agents, skills and workflow steps** are edited in a window that asks before a draft is lost. Cycles,
  milestones and runs are drawn on a timeline; Analytics and Usage as figures and a table; the Wiki as tree, text and
  outline. Sign-in and the desktop app's connect page are one card with "Stay signed in", on by default.
- **Errors and confirmations** show as a toast at the bottom right, a confirmation with Undo where there is one.

## Faster

The causes of the stutter when scrolling in the desktop app on Linux are gone: long lists and board columns draw only
what is in view, there are no edge fades on scrollers, no large blur behind windows (blur only on small menus, and only
with a GPU), no lift on hover and no animation that never ends, and opening a card no longer squeezes the board. Tests
hold each of these. It was measured and checked in a browser; it was not yet tried in the desktop app on Linux.

## Changed contracts

- `GET` and `PUT /v1/preferences`: a person's own preferences, for now "Show thinking expanded".
- `GET /v1/runs/finished`: the card runs that ended, for Fleet's Finished tab.
- `GET /v1/issues` takes `assignee=<handle>`, for My issues.
- `POST /v1/session` takes an optional `stay` (default true); `false` gives a session that ends with the browser.

They are in [the desktop API reference](../reference/desktop-api.md).

## Upgrading from 0.15

Upgrade the server and the desktop app together: the web app is served by the server and calls the routes above. The
store gains a table for the preferences when the server starts; nothing else needs doing. A browser keeps working; a
reload after the upgrade fetches the new web app.
