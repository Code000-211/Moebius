# Moebius 0.19.1

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.
Its contracts may change in any later release without a way to migrate.

This release lets measurements and reviews flow without the owner's clicks, and shows on the forge where every issue
stands ([ADR 0033](../adr/0033-measurements-and-reviews-flow-without-the-owners-clicks.md), the
[factory reference](../reference/factory.md) and the guide [Working with others](../guide/working-with-others.md)).

## Measurements from measurers

- **A registered measurer's comment** on an issue whose change waits for a measurement (`approve_code`), starting with
  a `## Measurement` heading, is read at the poll. The server checks it first: the measurer is not the pull request's
  author, the measured `before` and `after` commits are the merge base and the current head, the required fields are
  there (GPUs, power cap, ROCm or driver version, container) and every side has at least three runs. What is wrong
  gets a reply; each comment is read once.
- **A measurement starts a review round** on its own, without the author's `/done`, and counts toward the round limit.
  The Reviewer judges it against the review brief: an approval merges through the gate with the measurement recorded
  for that head, `approve_code` says what is still missing. A new push makes the measurement invalid.

## Review on green checks

- **`review_on_green`** (per repository, off by default) starts a review round of a followed pull request once its
  head's checks have stayed green for a few minutes with no new push, once per head. `/done` still works; whichever
  comes first starts the round. Freeze, hold, Pause all and the round limit apply.

## Pull requests that name no issue

- **A pull request without "Fixes #N"** is bound to an issue when its title or branch names a backlog item the sync
  owns, or `#N` of an issue its author is assigned to. One that names none is asked once for `Fixes #N`, labelled
  `unbound` and closed after `unbound_close_days` (14), where the repository's commands and answers are on. One that
  names an issue it cannot be followed for is told why, once.

## Status labels on the forge

- **`status_labels`** (per repository, off by default) keeps exactly one label on every open issue with a card, so
  people outside Moebius see where it stands: its column (`status:in-review`, `status:ready-for-testing`, custom
  columns included) or, while they hold, `status:frozen`, `status:awaiting-measurement`, `status:changes-requested` or
  `status:taken`. A label removed by hand is put back at the next poll; a closed issue keeps its last one.

The settings are in the repository's "Review flow" box (`GET` and `PUT /v1/repositories/{id}/flow`).

## Upgrading from 0.19.0

Replace the server and the desktop app; the store gains the new tables when the server starts. Every new behaviour is
off until it is turned on. Any 0.19 app works with any 0.19 server.

**Full Changelog:** https://github.com/Code000-211/Moebius/compare/v0.19.0...v0.19.1
