# Moebius 0.9.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.

## What changed since 0.8.0

- **Turn plugins off and on** (#207). Each plugin on the Plugins page has a switch that works at once, without a
  restart; `moebius.toml` keeps the entry with `enabled = false`, and its settings stay. A decider that is off gives its
  kinds back to the built-in ones. Turning off a launcher is refused when it would leave some agents wrapped and others
  not, and turning off the last one asks first, since runs then start without a sandbox. Also
  `moebius plugin enable|disable <name>`.
- **GitHub with a personal access token** (#208). `[github]` takes `token_file` or `token_secret`, as GitLab and
  Forgejo do, instead of a GitHub App. Fine-grained tokens and classic tokens with `repo` both work; the reference lists
  the permissions. The server checks the token at start and says as whom Moebius acts on GitHub. With a token, pull
  requests and comments carry your own name, and GitHub does not let you approve your own pull request.
- **The chat** (#204, #205, #206, contributed by xzanomad):
  - The board always shows the Backlog column.
  - What the agent did folds into one "Working" row; a step that was refused or failed is counted on it and opens it.
  - The Moebius agent and the Grilling partner can ask questions with options to choose from; the chat list and the
    Inbox show that an answer is due.
- The design audit of the web app passes again with no findings, and two flaky tests are steady.
