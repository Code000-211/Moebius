# Moebius 0.8.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.

> [!IMPORTANT]
> **The desktop app is gone** (#195, ADR 0017). Use the web app: `moebius open` shows it in a window of its own, and
> `moebius connect <host>` does the same for a server on another machine. There is no desktop archive any more, and
> the Windows zip holds `moebius.exe` only.

## What changed since 0.7.0

- **`moebius connect <host>` sets a server up over SSH** (#195): when none answers on the other machine, it asks once
  and then installs `moebius` from this release (checked against its `SHA256SUMS`), makes the configuration, starts
  the server as a systemd user service `moebius-connect.service` (or detached where there is no systemd), and reads
  its token. `--yes` answers for scripts; `--upload` sends the program from this machine to a host without internet.
  A server that already runs, also one set up by hand, is used as it is.
- **Plugin settings in the web app** (#193, contributed by xzanomad). A plugin may ask for settings of each project
  (kept in the harness configuration repository under `repos/<name>/plugins/<plugin>/`) and of the whole server (on
  the new Plugin settings page). A plugin may draw its own settings page; it runs in an isolated frame with no access
  to your session or the API. The web app now sends a Content-Security-Policy.
- **Several launchers** (#193): a launcher may take only some agents (`launch_agents`), for example to leave the
  Moebius agent out of a sandbox. The last launcher must take every agent, and a run no launcher takes fails instead
  of starting unwrapped.
- **A run knows its issue's comments** (#193): the comments of the issue's author, of trusted logins, of the person and
  of Moebius are in the prompt, fenced and marked as data.
