# Moebius 0.19.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.
Its contracts may change in any later release without a way to migrate.

This release is the first part of a software factory: helpers' and agents' work goes from the backlog to a merge with
as little of the owner's work as possible, behind one merge gate the owner controls
([ADR 0031](../adr/0031-one-merge-gate-and-a-brake-for-the-factory.md),
[ADR 0032](../adr/0032-the-factory-keeps-the-owners-work-small.md), and the [factory reference](../reference/factory.md)).

## One merge gate

- **Every merge the server makes goes through one gate**: the automatic merge of a reviewed outside pull request, a
  person's Merge, a column script's merge. It fails closed and checks, in order: a freeze, hold and Pause all, green
  checks, an accepted measurement (or a `no-measurement` label) where the repository requires one, locked paths, and
  the repository's rules, which now hold for the server's own merges as they do for agents'.
- **Locked paths** never merge without a person: `.github/`, build files, `AGENTS.md`, `CLAUDE.md`, `.moebius/`,
  `kanban.toml`, the review brief and anything the owner adds.
- **Settings** per repository, in "Working with others": require a measurement, locked paths, the review brief, the
  ready-for-testing label and the measurers.

## A brake

- **Freeze a repository** by hand (`POST /v1/repositories/{id}/freeze`), with a `factory:freeze` label on one of its
  issues, or with Pause all. A frozen repository starts no review round, merges nothing and starts no agent run.
- **Breakers freeze it by themselves**: two reverts of merged changes in seven days, over 80% of the day's tokens, a
  failed nightly check. Every cause is kept on its own; removing the label lifts only the label's, and a person lifts
  the rest.

## The review knows the repository's rules

- **The review brief** (`REVIEW.md` by default, or the paths the repository names, such as `notes/backlog/CARDS.md`)
  is read from the default branch, never from the pull request, and given to the Reviewer as the repository's rules.
- **A new verdict, approve_code**: the code is right but the measurement the brief asks for is missing. The server
  approves the code, labels the issue `ready-for-testing`, moves the card to the project's "Ready for testing" column
  if it has one, says how to post a measurement, and merges nothing. A person accepts the measurement
  (`POST /v1/changes/{id}/measurement`) and the gate lets the change through; reading measurers' comments comes next.

## The factory runs itself

- **A daily digest** in each person's Inbox at `digest_at` (07:00 by default), cut to what they may see: merges and
  whether they were measured, gate refusals, reverts, review rounds, taken and released issues, freezes, token spend
  and what needs a person. A server's first day and empty days have none.
- **Stale handling** per repository: an issue taken without a pull request is released after 14 days; a pull request
  quiet after a review that asked for changes of its current head is reminded after 14 days and closed after 30.
  Frozen and held cards are left alone.
- **Backlog sync**: a project's backlog file (for example `notes/backlog/optimisation-backlog.md`) becomes one issue
  per item, quoting it whole, with `difficulty:*` and `lane-required` labels, at most 15 new issues a run. The sync
  owns only the issues it made and only the marked block in their text; items marked closed close their issue as not
  planned. `"$MOEBIUS" backlog`, a route and an example nightly workflow run it.

## Upgrading from 0.18

Replace the server and the desktop app: the app and the server must share a minor version, so install the 0.19 app
with the 0.19 server. The store gains the new tables when the server starts. Nothing changes for a repository until
its "Working with others" settings are set; the merge gate applies at once, so a server merge of a change that touches
a locked path now waits for a person.
