# Moebius 0.10.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.

## What changed since 0.9.4

- **Workflows** (#221–#237). A workflow is a graph of steps kept as `workflows/<name>.toml` in the harness
  configuration repository: one trigger starts a run, nodes do the work, and every edge carries a node's value down
  one of its output ports. A run waits only at an approval node and only until its deadline; while it runs it can be
  cancelled, which stops its nodes. [The guide shows how to build one](https://github.com/Code000-211/Moebius/blob/main/docs/guide/workflows.md).
- **The node kinds** (#221, #222, #223, #224, #226, #227, #228). An **agent** runs in a worktree the run owns (#224),
  a **code** node reshapes the value in Luau (#221), an **HTTP** node calls a service with named secrets and a URL
  policy (#223), a **condition** routes the value down one of its ports (#222), a **merge** joins two branches (#226),
  a **for-each** fans a value out over a list and gathers the results, an **approval** pauses the run for a person
  (#227), and a **publish** offers the run's branch as a change (#228).
- **The triggers** (#230, #231, #232). A run starts by hand with typed inputs, from a webhook, or on a schedule.
- **Automations are cron workflows** (#233). Behind the Automations page an automation is now stored and edited as a
  workflow whose trigger is `schedule` and whose single node starts an agent chat, so the page and the workflow cannot
  drift apart. Existing automations are migrated to workflow files on upgrade, and the old routes and command line keep
  their names and arguments as a shortcut.
- **The canvas** (#234, #235, #236). The web app draws a workflow with its nodes and edges and has a form for each
  node kind and trigger; the graph is saved by committing the workflow file to the harness configuration repository.
- Three example workflows run in CI (#237), beside the guide page that builds one step by step.
- A change's pull request is opened only after the review approves (#254), and the card and the inbox link to it
  (#259). A live card has a Stop run action (#253), and an inbox item's title opens the item (#252).
