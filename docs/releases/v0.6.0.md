# Moebius 0.6.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.

> [!IMPORTANT]
> **Your repositories no longer hold Moebius's settings.** A project's settings moved from the repository's own
> `.moebius/` folder to the harness configuration repository on the server. Nothing is imported: move the files by hand,
> as [Moving from `.moebius/`](https://github.com/Code000-211/Moebius/blob/main/docs/guide/column-scripts.md) says. Until
> you do, their rules, checks and test first do not apply, and the board shows a notice.

## What changed since 0.5.0

All of it in the web app and the server; the desktop app has no new screens.

- **A project's settings live on the server** (#190), in `repos/<repository name>/` of the harness configuration
  repository: `rules.md`, `review.md`, `lint.toml`, `checks`, `test-first`, `localize` and the column scripts. Every
  edit is a commit there. The project page has a **Project settings** box to edit them, the Rules page and the script
  editor save there, and the API has `GET /v1/repositories/{id}/settings` and `PUT` / `DELETE
  /v1/repositories/{id}/settings/{file}` with the event `project_settings_changed`.
- **Nothing is read from a repository's `.moebius/` any more.** A repository that still has one is named once in the log
  and with the event `settings_moved`, and its board and project page show a notice with the files left behind. A
  server that uses `rules_file` needs a `[harness]` section first.
- **Test first without a committed file**: the Coder names its reproduction test at the end of its summary
  (`REPRODUCE: <command>`, with `REPRODUCE-FILE: <path>` lines), and the test is checked as before: it fails on the
  base and passes on the change.
- **Long tool outputs** are kept in the run's own directory outside the worktree and removed with the run.
- **Packages and the Retro**: a workflow or rules package, and a Retro proposal for a project, become a change to the
  harness configuration repository, merged by a person.
- A refused push of an edit to the harness configuration repository answers `409` on every route.
