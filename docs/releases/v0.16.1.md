# Moebius 0.16.1

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.
Its contracts may change in any later release without a way to migrate.

This release fixes what showed up in the first days with the new look of 0.16.0, and changes two things about it: the
agent opens from a button in the page's header, and the surfaces are softer. The standard,
[`docs/design-web.md`](../design-web.md), and the decisions in
[`docs/design/web-redesign/`](../design/web-redesign/DECISIONS.md) say the same.

## Changed

- **The agent opens from the header.** The "Ask Moebius" field at the foot of every page is gone. A quiet "Moebius"
  button in the page's header opens the agent as a panel beside the content and shows that it is open; pressing it again,
  Esc or Ctrl+J closes it. Below about 1000px the panel lies over the content from the right.
- **Softer surfaces.** The content no longer floats as a panel on a tinted canvas: the sidebar and the content meet at
  one hairline, and the chosen item in the sidebar is a grey pill. Windows in the page are 16px round with a soft
  shadow; buttons, fields and menus are 8px.
- **Round corners on the desktop window.** The desktop app's window is transparent and its page draws round corners,
  square when the window is maximised or full screen. On Linux this needs a compositing window manager; without one the
  corners may show black. The app has not yet been tried on a real Linux or Windows desktop with this change.
- **One top bar for every window.** Every window in the middle of a page has the card window's bar: what it is, "Open as
  page" where there is a page, and close. Screens outside the shell (sign-in, "cannot reach", connecting) show all three
  window buttons, not only close.

## Fixed

- **"Approve plan" and "Reply" under any question.** The agent panel offered them under every answer that ended in a
  question, a greeting included. Nothing marks an answer as a plan, so they are gone; when the agent asks with its
  question tool, the options are drawn as a card and the chosen one goes back as the next message.
- **"Plan ready" on every outside issue.** An issue from outside waiting for approval now reads "Waiting for approval"
  with an "Approve" button, the same on the Inbox, the board, Fleet and the card window. The id column is as wide as the
  longest key and cuts the project part, never the number.
- **Unreadable reasons in a card's thread.** A move reads "Moved to …" or "Sent back to …"; a long reason is a collapsed
  part of the line that opens as formatted text. A card's note, a Retro proposal and a grilling report are formatted
  too, and long words and inline code wrap in narrow panels.
- **A Retro proposal opened an empty window.** In the desktop app on Linux the window drew only its first row
  ("Assignee"). It now shows the proposal first: where it came from, the reason, the change and Merge or Dismiss.

## For contributors

- A pull request runs only the CI jobs its changed files need; a push to main still runs every job. The mapping is in
  `.github/workflows/ci.yml` and [`CONTRIBUTING.md`](../../CONTRIBUTING.md).
- Several end-to-end tests that failed now and then under load wait for what they check instead of reading it once.

## Upgrading from 0.16.0

Upgrade the server and the desktop app together; nothing else needs doing. A browser keeps working; a reload after the
upgrade fetches the new web app.

**Full Changelog:** https://github.com/Code000-211/Moebius/compare/v0.16.0...v0.16.1
