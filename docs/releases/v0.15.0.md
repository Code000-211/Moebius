# Moebius 0.15.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.
Its contracts may change in any later release without a way to migrate.

This release makes Moebius fast and fixes what testing a real 0.14.0 server turned up. The board's tick, the store,
the snapshot and the web app's reads were measured on a server with hundreds of cards and changed where the time went;
the web app and the desktop app no longer slow down as the board fills. Read "Upgrading from 0.14" before you install
it over a running server: a few contracts changed.

## Faster

- **The board's tick** leaves a card whose script did nothing alone until a row it reads is written, or 60 s pass:
  with 660 waiting cards an idle server uses 1.5 % of a core instead of 43.7 %.
- **Conflicts are found when a script reads them.** `change.conflict` runs `git merge-tree` the first time a script
  reads it and keeps the answer until a head moves: 25 git processes a minute instead of 204 with six open changes.
- **The store** reads through a pool of its own instead of waiting behind run-event writes, and writes a run's events
  in batches: 3,000 token deltas take 247 ms instead of 780 ms.
- **The snapshot** reads its cards in bulk: 37 ms instead of 283 ms for 2,400 cards.
- **Answers are compressed and cached**: API answers and the web app's files of 1 KiB or more go out with brotli or
  gzip, and every file of the web app carries an `ETag`. The web app's files shrink from 1.19 MB to 363 KB.
- **The event stream** sends a run's token deltas only to a client that asked for that run, so a board no longer
  receives every token of every agent.
- **The web app** reads what an event touched at most once a second instead of on every event (3,289 snapshot reads in
  30 s became 30), redraws only the cards that changed (71 renders instead of 3,538 for one card), starts a card's
  reads beside the snapshot on a cold load, and shows your own edit and a new card at once from the server's answer.
- **The desktop app** reads the tray's and the rail's figures from a small `GET /v1/status` instead of the snapshot,
  keeps a page per opened server so switching back takes 0.02–0.6 s instead of up to 3.6 s with a blank window, and
  turns WebKitGTK's compositing off on Linux machines without a GPU (`MOEBIUS_RENDERING` overrides it).

## Fixed

- **Workflows**: the Workflows page no longer crashes; a workflow's page lists its runs, starts and cancels them
  (`GET /v1/workflow-runs`, `GET /v1/workflow-runs/{id}`, `last_run` on `GET /v1/workflows`).
- **`run_limit`** holds for every column: `moebius.start_run` starts no run while the limit's runs of cards go.
- **The wiki** refuses a save built on an older version of the page with `409` instead of overwriting it, and the
  editor asks before unsaved text is left. There are screens for wiki search, templates and the Jira import.
- **The Inbox** counts one thing everywhere, filters notices by kind, and marks what you open as read.
- **The board and the card**: Escape in a property menu closes only the menu; Issues, Views and milestones open the
  card you clicked; the card's drawer no longer covers the board's head bar; dialogs have their padding back and
  nothing is clipped at 800 or 1024 px.
- **Controls that were missing**: pause all agents, Stop on a Fleet row, and Stop, Rename and Delete in a chat's head.
- **The desktop app** no longer hangs for three minutes when the system keychain does not answer (it gives up after
  8 s and offers to connect for this session only), tells servers apart in the rail, and batches notifications.
- Many small fixes on the planning pages, Settings, the palette, People and the card, and several end-to-end tests
  that failed now and then.

## Upgrading from 0.14

Stop the server, replace the program, start it again; the store adds one index on its own when it starts. Then:

- **Install the desktop app of 0.15 with the server of 0.15.** The app and the server must share a minor version, and
  the app of 0.15 reads `GET /v1/status`, which a server of 0.14 does not have.
- **A client that shows token deltas must ask for them.** On `/v1/events`, send `{"subscribe": [run ids]}` (and
  `{"unsubscribe": [...]}`); the server answers `subscribed`. Everyone still gets `agent_start`, `agent_settled`,
  `moebius_error`, `run_started`, `run_ended` and every other event.
- **A column script is not run at every tick.** A card whose script did nothing runs again when a row it reads is
  written, or after 60 s: a script that acts only on the clock or a due date notices within 60 s, not within a tick.
- **`moebius.start_run` returns nil at the run limit**, in every column. A script should return when it does:
  `if moebius.start_run(...) == nil then return end`.
- **A wiki save may send `base`**, the commit of the page it was built on; with it, a page changed since is refused
  with `409` and the current version. Without `base` a save replaces the page as before.
- **Read notices are deleted 30 days after they were made**; unread ones stay.
