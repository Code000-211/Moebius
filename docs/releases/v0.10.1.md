# Moebius 0.10.1

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.
Its contracts may change in any later release without a way to migrate.

**This release carries everything since the last published one (v0.9.4).** The workflows release was prepared and
noted as 0.10.0 — its notes stand in [docs/releases/v0.10.0.md](./v0.10.0.md) — but no build of it was ever tagged or
published, so 0.10.1 ships all of it together with the newer work.

## A workflow for every job

Moebius drives more than the board now: a workflow is a graph of steps kept as `workflows/<name>.toml` in the harness
configuration repository (#221–#237). One trigger starts a run — by hand with typed inputs, from a webhook, or on a
schedule — and every edge carries a node's value down one of its output ports. A run waits only at an approval node
and only until its deadline, and while it runs it can be cancelled, which stops its nodes. The node kinds:

- an **agent** node runs an agent in a worktree the run owns (#224);
- a **code** node reshapes the value in Luau (#221);
- an **HTTP** node calls a service with named secrets and a URL policy (#223);
- a **condition** routes the value down one of its ports (#222);
- a **merge** joins two branches (#226), and a **for-each** fans a value out over a list and gathers the results;
- an **approval** pauses the run for a person (#227);
- a **publish** node offers the run's branch as a change (#228).

Three example workflows run in CI (#237), and [a guide page](https://github.com/Code000-211/Moebius/blob/main/docs/guide/workflows.md)
builds one step by step.

### Workflows in the app

The web app draws a workflow on a canvas, with its nodes and edges, a form for each node kind and a form for each
trigger; a save commits the workflow file to the harness configuration repository (#234, #235, #236). A workflow is
created from a dialog on the Workflows page (#278) and deleted from its detail page (#279), and the Workflows page
stands in the sidebar under Automations, not only in the command bar.

## Automations are workflows

Behind the Automations page an automation is now stored and edited as a workflow whose trigger is `schedule` and
whose single node starts an agent chat (#233), so the page and the workflow cannot drift apart. Automations from
earlier versions are migrated to workflow files on the first start after upgrading; the old routes and command line
keep their names and arguments as a shortcut to the new runs.

## A change's pull request when the review approves

A change's pull request is opened only after the review approves (#254), the card and the inbox item link to it
(#259), a live card has a Stop run action (#253), and an inbox item's title opens the item (#252).

## A grilling ends or publishes when you say so

A grilling chat no longer has to be poked into ending: the chat has an **End grilling** action that ends it, and a
**Publish** action that stores what the agent has left the way ending would, without ending the chat and while it
takes messages as before. Nothing reaches the forge until you say so, and each later publish replaces what was
stored while nothing has confirmed it yet — so you can go on polishing after you have the issues.
[The grilling guide](https://github.com/Code000-211/Moebius/blob/main/docs/guide/grilling.md) has the details.

## Commits that say what a chat did

The commits Moebius writes for a chat's work no longer repeat the chat's first message or a bare `Chat <id>`: the
subject is the first line of the agent's last answer, the body carries the rest of it, the trailer names the chat,
its title and its agent, and the last line says when the commit was made ("Made by Moebius when the chat ended." or
"… when the chat's work was offered."). The Coder and the Moebius agent are instructed to end a long change with an
answer whose first line reads as a commit subject. A chat's change merged without a card names what it carries,
`Merge <branch>: <the branch's last commit's subject>`, and a chat's pull request body tells what the chat did and
which files changed.
