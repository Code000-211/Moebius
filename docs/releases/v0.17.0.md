# Moebius 0.17.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.
Its contracts may change in any later release without a way to migrate.

This release puts everything where it belongs ([ADR 0024](../adr/0024-navigation-by-what-you-do.md)): Settings holds
only what one sets and leaves alone, what one builds or reads has a place of its own, and everything a project owns
lives in the project. Workflows now belong to a project ([ADR 0025](../adr/0025-workflows-belong-to-a-project.md)), and
the server moves the ones you have into their projects when it starts. Read "Upgrading from 0.16" before you install
it over a running server: the move is a commit in the harness configuration repository, and six workflow routes are
gone.

## Projects own their things

- **Tabs in the project's header**: Board (with Board and List), Workflows, Cycles, Milestones, and Intake while it is
  on. A gear leads to the project's settings, and the "..." menu holds Import from Jira and Terminal.
- **Project settings** with a sub-navigation: General (name, key, private, the intake switch, the kinds of issues the
  project offers, the Jira import), Members, Repositories (each repository's page with its code settings and files)
  and Columns (the project's column scripts, their only editor now).
- **Cycles, Milestones and Intake** are tabs of the project; the pages across projects are gone.
- **Addresses**: a project's board is `/projects/<project>`, a repository's page `/projects/<project>/repositories/<repository>`.
  Old addresses (`/board/<repository>`, `/cycles`, `/milestones`, `/intake`, `/issues`, `/workflows`, `/automations`
  and the old settings pages) lead to their new place.

## Workflows belong to a project

- A workflow is `projects/<project>/workflows/<name>.toml` in the harness configuration repository; the same name can
  be used in two projects. A run belongs to one of the project's repositories, and a run that could be any of several
  is refused with the choices.
- **The project's Workflows tab** lists its workflows and their runs, filters to the scheduled ones, opens a workflow's
  canvas and starts a run with "Run a workflow here". Automations are scheduled workflows of a project.
- **Webhooks** are `POST /api/hooks/projects/<project>/<path>` (and `…/<project>/<repository>/<path>`). The old
  addresses keep answering while one workflow claims the path, and answer `409` with the new addresses when several do.
- The API, the webhooks, packages and `moebius workflow … --project <project>` work on a project's workflows; with one
  project, the command line takes it without `--project`.

## A sidebar by what you do

- **Inbox, My issues, Fleet, Chat**, then one row per project, **Workspace** (Wiki, Views), **Build** (Agents, Rules)
  and **Insight** (Insights, Improve) for owners, and Settings at the foot. "More" is gone.
- **Fleet** has the tabs Runs (card and workflow runs of every project you see), Runners and Ports.
- **Agents** has the tabs Agents, Skills and MCP servers; Rules stands beside it.
- **Insights** has Analytics and Usage, **Improve** has Retro, Lessons, Experiments and Decisions (with the training
  export).
- **Views** starts with "All issues", across every project you see.
- **Settings** holds You (Profile, Appearance, Keyboard shortcuts, My tokens) and, for owners, Server (General with the
  nightly times, Models, Plugins, Kinds of issues, Members).
- The page header orders the page's own buttons, the gear and menu, Moebius, then the primary button; menus are opaque
  in the dark theme.

## Fixed

- **Ctrl+K and Ctrl+J** were lost when pressed right after closing a card's Properties: the closing card menu kept the
  key. Shortcuts with Ctrl or Cmd now always reach the palette and the agent.
- **Escape right after a card window opened** was lost; it closes the window now.
- **Inline code** is drawn quietly in the text's colour; only fenced code blocks are dark.
- **Removing a repository** that had workflow runs failed; its finished runs go with it now, and removal is refused,
  naming the run, while one of them is active.
- Several end-to-end tests that failed now and then, one of them only after midnight UTC.

## Known gaps

- The sub-navigation of Settings and of project settings has no icons, and Settings has a search field the mockup does
  not show.
- Some tab pages show a thin empty band under the header; at 800 px the project header wraps to two rows.
- Appearance has no Density and no "Wrap long lines" yet.
- A scheduled workflow that is not an automation does not show when it fires next.
- The outgoing webhooks panel does not show the project in a hook's address yet.

## Upgrading from 0.16

Back up the data directory first ([Running Moebius](../guide/running-moebius.md)): the store changes when the server
starts and cannot be rolled back. Then:

- **Existing workflows and automations move into their projects** when the server starts, in one commit pushed to the
  harness configuration repository's `origin`, which restoring the data directory does not undo. A workflow goes to the
  home project of the repository it names (the oldest of the projects that hold it, a private one only when only
  private ones do); one that names no repository goes to the oldest project that is not private. Its runs, its
  schedule (with the time it last fired, so nothing fires twice) and its automation go with it. A workflow with no
  project to go to stays where it is, with a warning and an item in Get started, and the server tries again at every
  start.
- **Six routes are gone** and answer `410` with the route that replaces it: `GET /v1/workflows`, `GET`, `PUT` and
  `DELETE /v1/workflows/{name}`, `GET /v1/workflows/{name}/run-inputs` and `POST /v1/workflows/{name}/runs`. Use the
  same routes under `/v1/projects/{id}/` ([desktop API](../reference/desktop-api.md)).
- **Point your webhook senders at the new addresses** under `/api/hooks/projects/<project>/`; the old ones answer only
  while the path is unique.
- **A project that owns workflows or has an active run** cannot be deleted with its repository.
- **Install the desktop app of 0.17 with the server of 0.17**: the app and the server must share a minor version.
