# Moebius 0.2.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.

## What changed since 0.1.9

- **The web app is the front end.** The server serves it at `/`; `moebius serve` prints an address that signs you in
  once, `moebius open` opens it in a window of its own, and `moebius connect <host>` opens it for a server reached over
  SSH. Every page of the desktop app is there: board, chat and floating chat, projects with their files and changes,
  inbox, fleet, usage, agents, skills, MCP servers, models, plugins, rules, automations, Retro, experiments and the
  decision model. The desktop app stays for this release (ADR 0013).
- **A design of its own for the web app** (`docs/design-web.md`, ADR 0016), contributed in #173: a card opens in a
  drawer the height of the window with its issue and its change, a chat's steps read as a log, a change is read beside
  its files, and the same control and the same word are used on every page. A chat can be given its own name.
- **The column "Ready" is now "Not started"** and the tag "Waits for you" is "Your turn". A repository's own scripts
  that name "Ready" keep working: `moebius.move("Ready")`, `check-script --column Ready` and the scripts route take it as
  the old name. Cards and their history move to the new name when the server starts.
- **Packages.** `moebius pkg` finds, installs, updates and removes plugins, workflows, rules and skills from registries;
  the first is [moebius-plugins](https://github.com/Code000-211/moebius-plugins), with its sha256 checked on every
  download (ADR 0015, `docs/reference/packages.md`). `moebius ext` does the same for Pi packages from pi.dev, vendored
  into the harness configuration repository and pinned in `packages.lock`; an agent names one as `pkg:<name>`. Both
  check once a night and put an update in the Inbox.
- **Launcher plugins.** A plugin of the new kind `launcher` wraps how a Pi-Bolt process starts, failing the run when it
  cannot (ADR 0014). The first is `nono-sandbox`, which runs every Pi-Bolt process in its own
  [nono](https://github.com/nolabs-ai/nono) sandbox: `moebius pkg install nono-sandbox`, with nono 0.81.0 installed.
- **Many backend fixes** from a review of the whole server: secrets kept out of harness environments and stored text,
  private credential files, the guard seeing the real tool call, runs that stop and clean up their processes, SSH
  runner tunnels, forge polling, repository file paths, router and MCP gateway protocol handling, replays confined to
  their copy, and indexes for the store's hot queries.
