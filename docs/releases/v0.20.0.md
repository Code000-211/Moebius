# Moebius 0.20.0

Still an early prototype: use it only with throwaway repositories and with model accounts whose spending you watch.
Its contracts may change in any later release without a way to migrate.

This release finishes the software factory. Moebius's own agents now work on the forge the way people do. A test lane
builds, tests and measures each reviewed change on the owner's own machines.

## Templates, and agents that work on the forge

[ADR 0034](../adr/0034-templates-and-agents-that-work-on-the-forge.md), the
[templates reference](../reference/templates.md).

- **Templates for pull requests, issues and comments.** Moebius reads each template by its headings into fields:
  `card.change.fields`, `card.issue.fields`, `.missing` and `.measurement`, also shown in the card window.
  - A followed pull request that lacks a section is told so once (`## Missing`).
  - The comment kinds have documented fields, and a malformed comment gets a reply that names the field: `## Measurement`,
    `/done` or `## Done`, `## Review answer`, `/take` and `/release`.
  - A project overrides any template in `projects/<project>/templates/`.
  - `moebius templates --sync` and `POST /v1/repositories/{id}/templates/sync` open a gated pull request for `.github/`,
    with the issue form included.
- **Own agents on the forge.** This is the repository flow setting `work_on_forge`, on by default where the forge has
  draft pull requests.
  - **Draft and body:** the pull request opens as a draft after the first round. Its body is written from the template
    and rewritten each round.
  - **Reviews:** the verdict is a real review with line comments, once per round and head. Where the forge refuses a
    verdict on the author's own pull request, it is posted as a comment review that starts with `**Approved.**` or
    `**Changes requested.**`.
  - **Answers:** the next round answers each finding (`## Review answer`). The Reviewer gets the pull request's fields
    fenced as the author's claims.
  - **Merge:** approval takes the pull request out of draft, and it merges through the gate. The merge message comes
    from the template's fields.
  - **The issue** gets only the status and a link. The link is written once, and only after the pull request exists.
  - **Branches** of backlog items are named `moebius/<ID>-card-<n>`.
- **An example** for a repository with a measured merge bar is in `examples/project-templates/`.

## A test lane on the owner's GPUs

[ADR 0035](../adr/0035-a-test-lane-measures-on-the-owners-own-gpus.md), the
[lanes reference](../reference/lanes.md), the guide [Test lane](../guide/test-lane.md).

- **Lanes** (`[[lanes]]`): a runner over SSH, or the server itself.
  - A lane runs one job at a time, with a queue.
  - A person assigns lanes per repository in the new "Test lane" box.
  - The job is defined in `projects/<project>/lane.toml`, which only a person may save.
- **What a job does.**
  - It builds, tests and measures a change at its pinned head after the Reviewer approves the code.
  - Measuring steps run the merge base and the head in turns, at least three runs each.
  - A failure goes back to the author with one reply.
  - A measurement starts the next Reviewer round, and an approval merges through the gate.
  - A new push cancels the job.
- **Isolation per lane:** `always` (the default) runs a fresh container per command; `external_only` and `off` are
  the others. Settings and the digest warn while a lane is not `always`.
  - **The container:** no network, no capabilities, an unprivileged user, a read-only root and no container log.
  - **Limits:** memory, swap, processors, file size and processes. A probe container checks them before every job.
  - **The harness:** the merge base's harness is mounted read-only, with its parent directories pinned, and is
    re-hashed after every run.
  - **Output:** output the code under test could have cut or merged into a row fails the step.
- **Disk.**
  - A watcher stops a job that writes more than `disk` or leaves less than the disk's reserve.
  - A lane on the server itself must keep its `work_dir` outside `data_dir`, on a disk of its own, unless
    `shared_disk = true`.
- **Recovery.** Clean-up and server start remove every container and process of a job.
  - Three failures of the lane itself in a row pause the lane, and the owner is told.
  - Nothing the code under test does can pause the lane.

## Not verified on real hardware

The test lane was tested against a fake container runtime, a fake `ssh` and fake `du` and `df`. Nothing ran on real
podman or docker, real GPUs or real SSH. Watch the first real jobs. If a lane refuses to start, the probe may be
reporting that the runtime does not apply the limits, for example rootless podman without delegated cgroup v2
controllers.

## Upgrading from 0.19

Replace the server and the desktop app. The app and the server must share a minor version, so install the 0.20 app
with the 0.20 server. The store gains the new tables when the server starts.

`work_on_forge` is on by default. From the next round on, own agents' pull requests open as drafts, and their reviews
are posted on the forge. Turn it off in the repository's "Review flow" box to keep the old behaviour. No lane runs
until one is configured and assigned.
